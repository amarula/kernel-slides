# What is I2C?

- A very common **low-speed bus** to connect on-board and external devices to the processor.
- Two wires: **SDA** (data) and **SCL** (clock).
- A **master/slave** bus: only the master initiates transactions; slaves only reply.
- In Linux, the SoC's I2C controller is usually the master.
- Each slave is identified by a unique **I2C address**; every transaction carries it.

# The I2C bus driver

- The I2C core provides APIs for controller drivers, kernel device drivers, and user-space device
  drivers.
- Core: `drivers/i2c/`; controller drivers: `drivers/i2c/busses/`; device drivers throughout
  `drivers/`.

Registering a device driver (`struct i2c_driver` inherits `struct device_driver`):

```c
static struct i2c_driver adxl345_i2c_driver = {
    .driver = { .name = "adxl345_i2c", .of_match_table = adxl345_of_match },
    .probe  = adxl345_i2c_probe,
    .remove = adxl345_i2c_remove,
    .id_table = adxl345_i2c_id,
};
module_i2c_driver(adxl345_i2c_driver);
```

# Registering I2C devices

- **Non-DT:** `struct i2c_board_info` + `i2c_register_board_info()` at platform init
  (`I2C_BOARD_INFO("rs5c372a", 0x32)`).
- **DT:** the controller node is defined in the `.dtsi` (usually `status = "disabled"`); the board
  `.dts` enables it (`status = "okay"`), sets `clock-frequency`, and describes devices as children
  whose `reg` is the slave address:

```c
&i2c0 {
    pinctrl-names = "default";
    pinctrl-0 = <&i2c0_pins_a>;
    status = "okay";

    axp209: pmic@34 {
        compatible = "x-powers,axp209";
        reg = <0x34>;
    };
};
```

# Communicating with the I2C device

- **Raw API:**
  ```c
  int i2c_master_send(const struct i2c_client *client, const char *buf, int count);
  int i2c_master_recv(const struct i2c_client *client, char *buf, int count);
  ```
- **Message transfer** (several messages in one transaction):
  ```c
  int i2c_transfer(struct i2c_adapter *adap, struct i2c_msg *msgs, int num);
  ```
- Not all controllers support all features: check with `i2c_check_functionality()` before using
  e.g. `I2C_FUNC_I2C` or `I2C_FUNC_SMBUS_BYTE_DATA`.

# i2c-gpio: a bit-banging I²C driver

- A Linux kernel driver for **bit-banging** an I²C bus using the GPIO API
  (`drivers/i2c/busses/i2c-gpio.c`).
- Toggles the **SDA** and **SCL** lines in software, handles incomplete I²C transfers, and can
  inject faults for testing.
- Supports platform data, ACPI, and Device Tree setups.

# The GPIO API

- GPIO functions (all prefixed `gpiod_`) configure, read and write GPIO pins.

```c
gpiod_direction_output(desc, 0);   /* set a pin as output, value 0 */
gpiod_set_value(desc, 1);          /* drive the pin high */
gpiod_get_value(desc);             /* read the pin state */
```

- `gpiod_cansleep(desc)` tells whether a pin access may sleep (slow GPIO chips).

# The platform driver

```c
static struct platform_driver i2c_gpio_driver = {
    .driver     = {
        .name           = "i2c-gpio",
        .of_match_table = i2c_gpio_dt_ids,       /* Device Tree match */
        .acpi_match_table = i2c_gpio_acpi_match, /* ACPI match */
    },
    .probe      = i2c_gpio_probe,
    .remove_new = i2c_gpio_remove,
};

static int __init i2c_gpio_init(void)
{
    int ret;

    ret = platform_driver_register(&i2c_gpio_driver);
    if (ret)
        printk(KERN_ERR "i2c-gpio: probe failed: %d\n", ret);

    return ret;
}
subsys_initcall(i2c_gpio_init);
```

# SDA / SCL helpers

The bit-banging algorithm is wired through `struct i2c_algo_bit_data`:

```c
static void i2c_gpio_setsda_val(void *data, int state);  /* drive SDA */
static void i2c_gpio_setscl_val(void *data, int state);  /* drive SCL */
static int  i2c_gpio_getsda(void *data);                 /* read SDA */
static int  i2c_gpio_getscl(void *data);                 /* read SCL */
```

- `state` is `0` for low, `1` for high.
- `data` is the driver private data (`struct i2c_gpio_private_data`).

# probe()

```c
priv = devm_kzalloc(dev, sizeof(*priv), GFP_KERNEL);
if (!priv)
    return -ENOMEM;

adap = &priv->adap;
bit_data = &priv->bit_data;
pdata = &priv->pdata;
```

- `devm_kzalloc()` allocates and auto-frees driver-specific data.
- The firmware node (DT or ACPI) is read with `device_property_read_bool()` /
  `device_property_read_u32()` (no need to care which firmware is used).

```c
if (fwnode)
    i2c_gpio_get_properties(dev, pdata);
else if (dev_get_platdata(dev))
    memcpy(pdata, dev_get_platdata(dev), sizeof(*pdata));
```

Then the SDA/SCL lines are requested via `i2c_gpio_get_desc()`, the bit-bang algorithm is
configured (`setsda`, `setscl`, `getsda`, `getscl`, `udelay`, `timeout`), and the adapter is
registered with `i2c_bit_add_bus()`.

# Device Tree match

```c
static const struct of_device_id i2c_gpio_dt_ids[] = {
    { .compatible = "i2c-gpio", },
    { /* sentinel */ }
};
```

```c
i2c@0 {
    compatible = "i2c-gpio";
    sda-gpios = <&gpio 0 (GPIO_ACTIVE_HIGH | GPIO_OPEN_DRAIN)>;
    scl-gpios = <&gpio 1 (GPIO_ACTIVE_HIGH | GPIO_OPEN_DRAIN)>;
    i2c-gpio,delay-us = <5>;   /* ~100 kHz */
    #address-cells = <1>;
    #size-cells = <0>;
};
```
