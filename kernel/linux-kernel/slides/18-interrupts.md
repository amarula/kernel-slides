# Interrupts vs. exceptions

- An **interrupt** is an asynchronous event, usually raised by a hardware device, that diverts
  the current execution flow.
- An **exception** is synchronous: it is caused by the instruction currently executing
  (page fault, divide error, system call, undefined instruction).
- **Hardware interrupts** come from a device; **software interrupts** are generated by an
  instruction or by kernel code.
- **Maskable** interrupts can be disabled by the CPU; **NMIs** cannot.
- A line can be **shared** by several devices; a **spurious** interrupt has no acknowledged
  source.
- Typical examples: UART RX, timer and GPIO interrupts vs. page fault, system call and divide
  error exceptions.

# Interrupt controllers and trigger types

- The **interrupt controller** multiplexes device lines; it can mask, prioritize and set affinity.
- **Level-triggered**: the line is held at a level (high or low) until the device is serviced;
  the handler must mask and acknowledge the source.
- **Edge-triggered**: a transition (rising or falling) is the event; the controller must latch it
  so a short pulse is not lost.

| Trigger | Semantics | Typical source |
| --- | --- | --- |
| Level high/low | state remains until acknowledged | shared IRQ lines, some GPIO controllers |
| Edge rising/falling/both | event on a transition | GPIO buttons, some peripherals |

# From Device Tree to IRQ number

- The interrupt controller is a DT node with `interrupt-controller` and `#interrupt-cells`.
- A consumer node uses `interrupt-parent` (or inherits it) and `interrupts`.
- `interrupt-names` gives symbolic names for `platform_get_irq_byname()`.

```c
intc: interrupt-controller@a000 {
    compatible = "arm,gic-v3";
    interrupt-controller;
    #interrupt-cells = <3>;
};

uart0: serial@1000 {
    compatible = "vendor,uart";
    interrupt-parent = <&intc>;
    interrupts = <GIC_SPI 42 IRQ_TYPE_LEVEL_HIGH>;
    interrupt-names = "rx";
};
```

- `platform_get_irq()` / `platform_get_irq_byname()` return the Linux IRQ number; `of_irq_get()`
  is the OF-specific lookup.
- `irq_domain` translates the controller's hardware interrupt specifier into a Linux IRQ number.

# IRQ descriptors and flow handlers

- The kernel keeps one `struct irq_desc` per Linux IRQ; `struct irq_chip` contains the controller
  operations (mask, unmask, ack, eoi, set_type).
- The generic IRQ layer selects a **flow handler** based on the trigger type:
  - `handle_edge_irq()` — edge-triggered lines; tracks `IRQ_INPROGRESS` and `IRQ_PENDING`.
  - `handle_level_irq()` — level-triggered lines; masks and acknowledges before the action.
  - `handle_fasteoi_irq()` — controllers that only need an end-of-interrupt write.
  - `handle_simple_irq()` — no masking or acknowledgement handling.
- `irq_set_chip_and_handler()` wires a controller's `irq_chip` to a flow handler.
- On SMP, the flow handler prevents the same action from running concurrently on several CPUs.

# Registering an interrupt handler

```c
int devm_request_irq(struct device *dev, unsigned int irq, irq_handler_t handler,
                     unsigned long irq_flags, const char *devname, void *dev_id);
```

- `irq`: Linux IRQ number (from `platform_get_irq()` / `platform_get_irq_byname()`).
- `devname`: shown in `/proc/interrupts`, usually `pdev->name`.
- `dev_id`: opaque per-device pointer; must be unique and non-NULL on a shared line.
- Flag highlights:
  - `IRQF_SHARED` — the line is shared; all registered handlers are called.
  - `IRQF_ONESHOT` — keep the line masked until the threaded handler has run.
  - `IRQF_TRIGGER_*` — legacy trigger configuration (DT/ACPI should describe it).
  - `IRQF_NO_AUTOEN` — do not enable the IRQ automatically at request time.
- The handler returns `IRQ_HANDLED`, `IRQ_NONE`, or `IRQ_WAKE_THREAD`:

```c
irqreturn_t foo_interrupt(int irq, void *dev_id);
```

- `free_irq()` releases the handler; `devm_request_irq()` frees it automatically.

# Threaded IRQs

```c
int devm_request_threaded_irq(struct device *dev, unsigned int irq,
                              irq_handler_t handler, irq_handler_t thread_fn,
                              unsigned long irq_flags, const char *devname,
                              void *dev_id);
```

- The hard-IRQ `handler` runs first; returning `IRQ_WAKE_THREAD` wakes the dedicated kernel
  thread, which runs `thread_fn` in **process context**.
- `thread_fn` may sleep: take mutexes, call I2C/SPI/regmap functions that sleep, use `msleep()`.
- `IRQF_ONESHOT` is normally required: the line stays masked until `thread_fn` finishes.
- `thread_fn` returns `IRQ_HANDLED` (or `IRQ_NONE` if the interrupt was not ours).
- The IRQ thread is visible as `irq/<irq>-<devname>`; its priority can be tuned with
  `sched_setscheduler()` / `chrt`.
- Use it when the device needs slow, sleeping operations; keep the hard-IRQ part minimal.

# Top half and bottom half

- Hard IRQ handlers run with interrupts masked on the local CPU; they cannot sleep and should be
  short.
- **Top half** = the hard-IRQ handler; **bottom half** = deferred post-processing:
  - **softirqs** — interrupt context, interrupts enabled, cannot sleep; used by networking,
    timers, RCU…
  - **tasklets** — built on softirqs; legacy mechanism, prefer threaded IRQs or workqueues for
    new code.
  - **threaded IRQs** — process context, may sleep; see the previous slide.
  - **workqueues** — process context, may sleep; general-purpose deferred work.
- The top half should acknowledge the device and defer the rest.

# Top half vs. bottom half: contexts

| Mechanism | Context | IRQs | Can sleep | Typical use |
| --- | --- | --- | --- | --- |
| Hard IRQ | interrupt | disabled | No | fast handling |
| Softirq | interrupt | enabled | No | net, timers, RCU |
| Tasklet | interrupt | enabled | No | legacy deferred work |
| Threaded IRQ | process | enabled | Yes | blocking IRQ handling |
| Workqueue | process | enabled | Yes | background workers |

# Workqueues in practice

```c
struct foo {
    struct work_struct work;
};

static void foo_work(struct work_struct *work)
{
    struct foo *foo = container_of(work, struct foo, work);
    /* process context: may sleep */
}

static irqreturn_t foo_irq(int irq, void *dev_id)
{
    struct foo *foo = dev_id;
    schedule_work(&foo->work);
    return IRQ_HANDLED;
}
```

- `INIT_WORK(&foo->work, foo_work)` before scheduling.
- `schedule_work()` queues on the system workqueue; `flush_work()` / `cancel_work_sync()` wait
  for it.
- Delayed work: `INIT_DELAYED_WORK()` + `schedule_delayed_work()`.
- Custom queues: `alloc_workqueue()` with `WQ_MEM_RECLAIM`, `WQ_HIGHPRI`, `WQ_UNBOUND`.

# Latency and PREEMPT_RT

- The latency from an event to the application is roughly `T_irq + T_schedule`: time spent in
  hard-IRQ context plus time until the woken task runs.
- Mainline Linux does **not** nest interrupts: an IRQ handler is not preempted by another IRQ.
  Exceptions can be interrupted, and IRQs can interrupt exceptions.
- Long hard-IRQ handlers therefore delay every other interrupt on that CPU.
- **PREEMPT_RT** (merged in Linux 6.12) turns most spinlocks into sleeping locks and runs IRQ
  handlers in threads, reducing worst-case latency.
- With `CONFIG_PREEMPT_DYNAMIC`, `preempt=full|voluntary|none` selects the preemption model at
  boot; `CONFIG_PREEMPT_RT=y` is a separate build-time choice.
- Prefer threaded IRQs or workqueues for long or sleepable work.

# Debugging interrupts

- `cat /proc/interrupts` — per-CPU counts, controller, trigger type and the registered `devname`.
  - A count that stops increasing means the device is not raising the IRQ or it is masked.
  - A count that increases but the device does not work points to the handler or the protocol.
- `/proc/irq/<n>/spurious` — spurious-interrupt count for that Linux IRQ.
- `/proc/irq/<n>/smp_affinity` — CPU affinity mask; `irqbalance` adjusts it.
- `CONFIG_GENERIC_IRQ_DEBUGFS` exposes the IRQ hierarchy under `/sys/kernel/debug/irq/`.
- `trace-cmd` / `perf` / ftrace events: `irq_handler_entry`, `irq_handler_exit`, `softirq_entry`,
  `softirq_exit` show handler latency and softirq activity.
- `dmesg` reports "nobody cared" / spurious-IRQ warnings from the flow handlers.

# Summary and guidelines

- Keep the hard-IRQ handler **short**: acknowledge the device, save minimal state, defer the rest.
- Use **threaded IRQs** when the device needs to sleep; use **workqueues** for generic background
  work.
- Never sleep in hard-IRQ or softirq context; use `GFP_ATOMIC` only when necessary.
- Register with `devm_request_irq()` / `devm_request_threaded_irq()` and check the return value.
- For a shared line, use `IRQF_SHARED` and a unique, non-NULL `dev_id`.
- Let Device Tree/ACPI describe the trigger type; `IRQF_TRIGGER_*` is for legacy lines.
- Debug with `/proc/interrupts`, `/proc/irq/<n>/spurious`, ftrace IRQ events and
  `CONFIG_GENERIC_IRQ_DEBUGFS`.
